# 《观象录》微信小程序 MVP 产品与验收方案

版本：1.0
文档日期：2026-07-31
适用范围：第一版可提审 MVP
产品口号：借古人的象，理清今天的事。

## 1. 产品目标

《观象录》是一款以《周易》六十四卦为文化内容基础的传统文化互动与个人反思工具。用户通过选择现实问题、填写结构化状态、观看六爻成象动画，获得文化解释、主要矛盾、风险提示和可执行行动。

产品不预测未来，不判断吉凶，不提供改运、消灾、大师咨询或付费占卜。用户感到“贴合”的来源应是结构化输入、确定性规则和具体行动建议，而不是模糊话术或恐惧暗示。

第一版验证三件事：

1. 用户能否顺畅完成一次完整观象流程。
2. 结果能否准确复述现实条件并给出可执行建议。
3. 用户是否愿意保存结果、浏览文化内容或再次使用。

## 2. 第一版约束

### 2.1 技术与成本

- 微信小程序原生框架。
- TypeScript、WXML、WXSS、Canvas 2D。
- 六十四卦、规则、文案和素材全部随包分发。
- 用户问题、历史、收藏和设置只写入微信小程序本地 Storage。
- 不使用服务器、云函数、云数据库、域名或远程配置。
- 不接入大模型、第三方分析 SDK、广告 SDK 或埋点 SDK。
- 不做登录、手机号、支付、会员、订单或跨设备同步。
- 核心流程在断网状态下可用。

### 2.2 产品边界

第一版只提供：

- 今日观象。
- 情境分析。
- 情境生成和铜钱互动两种六爻生成方式。
- 结构化结果及三步行动。
- 六十四卦文化馆。
- 本地历史、收藏和设置。
- 不含私密问题的分享内容。

第一版不提供：

- 未来事件、疾病、寿命、财富、婚姻结果或他人行为预测。
- 医疗诊断、用药建议、法律结论、投资标的或赌博号码。
- 账号、云同步、推送、社区、评论、在线咨询或真人“大师”。
- 付费解锁、广告换结果、会员、商城或任何改运商品。
- 生辰、八字、姓名测算、人脸、手相、相机、定位或通讯录能力。
- 远程内容下载和后台内容管理。

## 3. 目标用户与核心场景

### 3.1 目标用户

- 18 岁以上、喜欢传统文化和东方视觉的用户。
- 面临工作、关系、人际、学习、家庭或个人状态选择的用户。
- 希望用有仪式感的过程整理事实和下一步行动的用户。
- 想学习六十四卦基础知识、保存个人反思记录的用户。

未成年人应在监护人指导下使用。涉及人身安全、医疗、法律、投资或严重心理危机的问题不进入普通结果流程。

### 3.2 六类情境

| 领域 | 用户目标 | 结果重点 |
|---|---|---|
| 工作事业 | 辞职、项目、转岗、合作等选择 | 替代方案、资源、验证成本和退出条件 |
| 感情关系 | 沟通、投入、边界、复合等困惑 | 事实与猜测分离、双方行动、明确表达 |
| 人际沟通 | 同事、朋友、合作、拒绝等问题 | 权责边界、沟通方式、留痕和冲突降级 |
| 学习成长 | 方向、考试、拖延、转行学习 | 目标拆分、试学验证、时间和反馈 |
| 家庭生活 | 分工、照护、搬家、家庭决定 | 资源分配、共同约定、可承受风险 |
| 自我状态 | 焦虑、疲惫、迷茫、启动困难 | 降低决策强度、恢复节律、小步行动 |

## 4. 信息架构

MVP 页面与职责如下：

| 页面 | 主要职责 | 必须可达入口 |
|---|---|---|
| 启动页 | 品牌动画、跳过 | 首次启动与正常启动 |
| 使用说明页 | 产品定位、理性使用提示、同意进入 | 首次启动 |
| 首页 | 今日观象、问一件事、文化馆、记录、设置 | 启动或返回首页 |
| 问题分类页 | 选择六个领域 | 首页“问一件事” |
| 问题输入页 | 输入 1—100 字现实问题、隐私提示 | 分类页 |
| 状态选择页 | 回答五道结构化选择题 | 问题输入页 |
| 六爻生成页 | 选择情境生成或铜钱互动，展示成象动画 | 状态选择页 |
| 结果页 | 展示卦象、解释、矛盾、风险、行动和保存 | 六爻生成完成 |
| 六十四卦列表页 | 检索或浏览全部卦象 | 首页 |
| 单卦详情页 | 文化原意、白话解释、关键词、六爻与启示 | 文化馆或结果页 |
| 历史记录页 | 查看、打开、删除、清空本地记录 | 首页 |
| 设置与隐私页 | 动画、音效、震动、省电、保存开关、协议与清空 | 首页 |

页面命名可以随代码架构调整，但上述功能入口、返回路径和异常路径不得缺失。

## 5. 完整用户流程

### 5.1 首次启动

1. 启动动画播放，用户可立即跳过。
2. 显示产品说明：
   - 这是传统文化互动与个人反思工具。
   - 内容不代表未来必然发生。
   - 不构成医疗、法律、投资或其他专业建议。
3. 用户点击“我已了解，开始体验”。
4. 本地记录已阅读状态，进入首页。

若用户不接受，应能退出说明页，不得用倒计时、遮挡或诱导文案强迫同意。

### 5.2 情境分析

1. 首页点击“问一件事”。
2. 选择问题领域。
3. 输入具体问题，长度 1—100 字。
4. 在输入提交前执行高风险内容识别：
   - 命中人身安全、自伤、医疗、法律、投资、赌博等场景时，显示专项安全提示。
   - 明确告诉用户该工具不能替代专业判断。
   - 不生成吉凶、治疗、诉讼胜负、买卖点或号码。
5. 普通问题进入五道结构化问题：
   - 当前更接近哪种行动状态。
   - 当前信息是否充分。
   - 事情主要由谁决定。
   - 失败后的影响有多大。
   - 当前情绪是什么。
6. 用户选择生成方式。
7. 完成六爻动画并进入结果。
8. 用户可保存、不保存、查看单卦文化详情或返回首页。

### 5.3 今日观象

1. 用户选择平静、焦虑、犹豫、有冲劲、疲惫或想改变。
2. 系统用当日日期和所选状态构造稳定输入。
3. 输出一个文化主题、一句反思问题和一个当天可执行动作。
4. 同一自然日、同一状态应得到一致结果。
5. 页面不得称为“今日运势”，不得输出财运、桃花或灾祸。

### 5.4 铜钱互动

1. 页面先显示“传统文化互动，不构成现实预测”。
2. 用户通过点击或上滑完成六次投掷。
3. 每次生成一条爻线，前两次完整播放，中间三次适当加速，最后一次加强收束效果。
4. 用户关闭震动、音效或动画后，流程仍可完成。
5. 低性能模式使用简化旋转和静态背景。
6. 不提供“重测到满意”“分享改结果”或付费重测。

### 5.5 历史与删除

1. 默认是否保存以设置项为准，结果页始终提供明确的本次保存选择。
2. 每条记录显示日期、领域、卦名和结果摘要。
3. 用户可查看详情、删除单条或清空全部。
4. 删除前需二次确认；确认后立即更新列表和本地 Storage。
5. 保留最近 100 条非收藏观象记录；收藏记录不占这 100 条配额。
6. 收藏卦象与观象记录分别管理，删除记录不得误删文化馆收藏。

## 6. 结构化分析规则

### 6.1 输入维度

五道选择题转换为内部维度：

| 维度 | 来源 | 说明 |
|---|---|---|
| 行动力 | 行动状态 | 推进意愿强弱 |
| 准备度 | 行动状态与信息充分度 | 是否已具备现实条件 |
| 清晰度 | 信息充分度 | 已知事实能否支持判断 |
| 控制度 | 决定权 | 用户可影响程度 |
| 风险度 | 失败影响 | 决定的可逆性和代价 |
| 关系度 | 决定权 | 是否依赖他人配合 |
| 压力度 | 当前情绪 | 焦虑、愤怒、疲惫等强度 |
| 阶段度 | 行动状态与风险组合 | 从刚出现到关键决策期 |

每个维度使用固定分值或枚举映射。禁止读取未填写信息，禁止根据姓名、生辰或设备信息推断。

### 6.2 八卦现实语义

| 基础卦 | 现实语义 |
|---|---|
| 乾 | 主动、创造、推进 |
| 坤 | 积累、承接、等待 |
| 震 | 启动、变化、突发 |
| 巽 | 沟通、试探、逐步进入 |
| 坎 | 风险、反复、不确定 |
| 离 | 看清、表达、展示 |
| 艮 | 停止、边界、重新评估 |
| 兑 | 交流、关系、认可 |

下卦代表用户内在状态，上卦代表外部条件。变化爻由阶段度和主要矛盾决定。相同结构化输入必须生成相同上下卦、变化爻和核心结论；只有铜钱互动模式允许随机。

### 6.3 结果组合

结果由以下确定性模块组合：

```text
六十四卦文化基础
+ 问题领域模板
+ 输入状态标签
+ 主要矛盾模板
+ 风险级别提示
+ 行动模板
+ 安全过滤
```

结果必须包含：

1. 当前之象：卦名、上下卦、关键词。
2. 传统原意：古籍原文出处和自编白话解释。
3. 当前状态：至少关联一个用户选择的现实条件。
4. 主要矛盾：说明两个冲突条件，不使用命运论。
5. 有利条件：指出已有资源或可控部分。
6. 风险提醒：描述行为风险，不预测灾祸。
7. 三步行动：
   - 今天完成的低成本动作。
   - 七天内完成的现实验证。
   - 重新决定的可观察条件。
8. 理性使用提示。

### 6.4 一致性与安全

- 情境模式的结果只由已知输入和固定内容版本决定。
- 用户返回修改任一答案后，必须基于新输入完整重算。
- 结果中不得出现违禁绝对词或恐吓词；详见 `content-rules.md`。
- 高风险拦截优先于分析规则。
- 内容缺失、数据解析失败或映射异常时，显示可恢复错误，不展示空白结果。
- 失败页允许返回修改输入或回到首页，不得随机补一个结果。

## 7. 本地数据模型

建议记录结构：

```typescript
interface ObservationRecord {
  id: string
  mode: 'context' | 'coin' | 'daily'
  category: 'career' | 'relationship' | 'social' | 'study' | 'family' | 'self'
  question: string
  answers: Record<string, string | number>
  hexagramId: number
  changingLine: number
  resultSummary: string
  actions: [string, string, string]
  createdAt: number
  favorited: boolean
}
```

本地 Storage 至少保存：

- 首次说明已阅读状态。
- 历史记录。
- 收藏卦象。
- 是否默认保存记录。
- 动画、音效、震动和省电设置。

数据规则：

- 不上传用户问题或选择。
- 不将用户问题写入日志、分享路径或分享卡。
- 读取失败时使用安全默认值，不覆盖可恢复的旧数据。
- 使用独立存储元数据记录结构版本；旧版无版本数据迁移时不得重写业务键，未来版本必须拒绝降级写入。
- 未知字段应被忽略，已知字段应校验类型；读取失败或结构损坏时禁止基于空默认值覆盖旧数据。
- 清空操作成功后重新读取确认，避免 UI 与 Storage 状态不一致。

## 8. 视觉与动效

### 8.1 视觉基线

- 墨黑：`#101415`
- 宣纸白：`#EAE5D8`
- 青绿：`#66847A`
- 暗金：`#B39A65`
- 朱砂：`#9A4F44`

系统字体优先：

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC",
  "Microsoft YaHei", sans-serif;
```

禁止使用来历不明的商业字体、影视音乐、短视频音轨或未经授权译文。

### 8.2 动效基线

- 启动动画 2—3 秒，可随时跳过。
- 页面切换不阻塞主要按钮。
- 六条爻线从下到上生成。
- 阳爻由两侧连接，阴爻从中间断开，变化爻用克制的朱砂提示。
- 只制作八套基础环境动效，由上下卦组合，不制作 64 套大资源动画。
- 支持关闭持续动画、音效和震动。
- 省电模式减少粒子、阴影和透明叠加。
- 不使用连续强闪光、恐怖符咒、鬼神形象或灾祸视觉。

## 9. 文案与隐私基线

- 首页使用“今日观象”“问一件事”“文化馆”“我的记录”。
- 不使用“算命”“测吉凶”“财运”“桃花运”“改命”“转运”“消灾”。
- 用户输入框提示不要填写姓名、生辰、地址、证件号等信息。
- 分享内容只含卦象视觉、卦名、关键词和行动提醒，不含原问题、答案和记录时间。
- 设置页可打开隐私保护说明、用户协议和内容声明。
- 第一版不申请定位、相机、相册、麦克风、手机号、通讯录、蓝牙或运动数据权限。
- 震动只在用户开启时调用，不用于读取或推断任何个人信息。

## 10. 异常与边界

必须处理：

- 空输入、纯空格、超过 100 字、仅表情或控制字符。
- 用户快速连点提交和重复导航。
- 中途返回后状态恢复或明确清空。
- 本地 Storage 不可用、超限、结构损坏。
- 六十四卦 JSON 缺项、重复 ID 或非法上下卦。
- 动画中切后台、锁屏、旋转或系统中断。
- 音频播放失败、震动不支持或 Canvas 初始化失败。
- 无网络、弱网和飞行模式。
- 小屏、长屏、字体放大、安全区和深色系统设置。
- 高风险内容的同音字、空格、大小写和常见变体。

错误提示应说明发生了什么和用户可以做什么，不显示堆栈、Storage 原文或内部路径。

## 11. MVP 验收标准

### 11.1 功能链路

- 首次说明、首页、六类情境、五道状态题、两种生成方式、结果、保存、文化馆、历史和设置全部可达。
- 普通情境从首页到结果无死路，返回操作符合用户预期。
- 六十四卦全部有名称、读音、上下卦、关键词、文化解释和行动启示，无空白详情。
- 相同情境输入重复 10 次，核心结果完全一致。
- 修改关键选择后，结果能体现变化且不存在旧状态残留。
- 每个正常结果都有三条不同时间尺度的行动。
- 高风险输入均进入对应拦截，不生成危险结论。
- 删除单条、清空全部、收藏和设置在重启后保持正确。
- 第 101 条记录写入时按规则移除最旧的非收藏记录。

### 11.2 隐私与合规

- 开发者工具 Network 面板中，核心流程无业务网络请求。
- 代码中不存在服务器地址、API 密钥、支付、登录、广告或 AI 调用。
- 分享内容不含问题原文和结构化答案。
- 隐私说明与实际 Storage、权限、分享行为一致。
- 全量结果文案通过禁用词扫描。
- 产品介绍、页面标题、按钮、截图和提审说明均采用传统文化互动与个人反思定位。
- 实际功能、提审服务类目和后台配置一致，不通过隐藏功能或虚假类目绕审。

### 11.3 体验与性能

- 启动动画可跳过，关闭动画后不影响流程。
- 普通设备上操作无长时间冻结；动画降级后仍可完成全部交互。
- 每个主操作都有按下、加载、完成或错误反馈。
- 主要文本不截断，底部按钮不被系统安全区遮挡。
- 连续完成 20 次分析不崩溃、不出现明显持续变慢。
- 飞行模式下，除微信平台本身限制外，核心分析、文化馆、历史和设置可用。

### 11.4 内容质量

- 六领域测试问题不少于 54 个，高风险拦截测试不少于 18 个。
- 结果复述现实变量，不输出“相信自己会更好”式万能结论代替分析。
- 行动建议可观察、可执行、不过度承诺。
- 无恐吓、绝对预测、诱导付费、诱导分享或反复测算话术。
- 古籍原文标注出处，现代白话和案例为原创或已确认可合法使用。

## 12. 上线前决策门

只有同时满足以下条件才进入提审：

1. 编译、静态检查和项目自带测试全部通过。
2. `test-cases.md` 中的核心、边界和高风险用例完成实测。
3. `manual-qa.md` 的开发者工具与至少两台真机检查通过。
4. 隐私说明与实际代码调用逐项核对一致。
5. 微信公众平台后台中的主体、名称、简介、服务类目、隐私保护指引和备案状态按提交时最新要求确认。
6. 提审包内不含测试按钮、调试入口、隐藏开关、空页面或未授权素材。

任何策划、测试或内部检查都不能承诺一定通过微信审核。审核结论以提交时微信平台的现行规则、主体资质、服务类目和实际审核结果为准。
